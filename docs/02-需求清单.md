# 02-需求清单：数据资产功能模块

## 总体目标
在 OpenMetadata 现有框架下，通过新增全套的数据资产管理体系，包含分类、目录、类型、属性以及具体的资产实例，并实现与之对应的前台导航及业务能力闭环。

## 需求分解清单

### [ASSET-001] 资产分类与资产目录建设
- **现状**：OM无对应实体和菜单。
- **目标**：实现 `AssetCategory` 与 `AssetCatalog` 实体的级联结构，及对应的目录树形展现和详情管理。
- **范围**：
  - 后端：分类、目录两级实体的建表与层级结构支持、导入导出、包含校验的物理删除。
  - 前端：资产分类菜单、分类详情页、目录详情页、添加与移动目录。

### [ASSET-002] 资产类型与资产属性建设
- **现状**：OM无对应实体和菜单。
- **目标**：实现 `AssetType` 与 `AssetAttribute` 实体的关联配置和动态表单支撑基础。
- **范围**：
  - 后端：类型、属性两级实体的组合关联、权限字段（填写人员）、导入导出。
  - 前端：资产类型菜单、类型详情（属性分类tab生成）、资产属性菜单及详情。

### [ASSET-003] 数据资产实体与详情管理
- **现状**：OM无对应实体和菜单。
- **目标**：实现最终业务数据 `DataAsset` 的落库展示，结合目录树进行筛选。
- **范围**：
  - 后端：数据资产实体建库，动态扩展字段存储，导入导出。
  - 前端：数据资产菜单及台账列表、数据资产详情页（动态展示所属类型的属性分类Tab与值编辑）。

### [ASSET-004] 概览与全局搜索中心
- **现状**：无入口。
- **目标**：仿造 Explore 页面，打造数据资产的统一门户入口。
- **范围**：
  - 全局 Elasticsearch 索引与高级条件搜索（AND/OR），基于目录树左侧筛选的联动数据资产查询交互。

### [ASSET-005] OM公共核心能力集成
- **现状**：需要针对新体系无缝注入OM公共基因。
- **目标**：确保数据资产各体系符合社区标准能力体验。
- **范围**：五大新实体必须全部支持原生的“点赞 (Up/Down Vote)”、“活动信息流 (Activity Feed)”、版本历史 (Version History)，且确保不需要软删除(逻辑删除)。
