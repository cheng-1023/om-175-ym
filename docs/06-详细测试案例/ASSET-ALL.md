## 5. 性能熔断安全验证 (Non-Functional)
> 没有人能够逃避数据无极激增而导致的原系统性能大出血反应。

- **[SQL 与 DAO N+1 滥查压崩测试] (TC-PRF-001)**：
    当一个 Asset Catalog 下背负着 1 万名 `DataAsset` 子实体时。调用查获 Catalog 详情并且携带 `?fields=dataAssets` (下推延展) 属性。
    **防御目标**：API 返回时间 (`RT - Response Time`) 不应劣变超过 `1500 MS`; SQL 监听记录中不应该因为延展那 1 万名小卒子而连带跑出 1 万次小碎步 `SELECT ... FROM DataAsset where id = ?` 引发的 `N+1 Query` 风暴。
- **[XSS / 跨站污染防护体系] (TC-SEC-001)**：
    利用 CSV 批量拉入模块或是 `DataAsset` 各种自由多填框注入 `<script>window.location='pwned'</script>` 等危险脚本。
    **防御目标**：打开包含该资产详情或树木面板时，框架必须全面 Escape 转译标签体使其平稳当作文本输出！任何因为这东西被渲染引发了乱跳或是 Cookie 发送均按最高级 P0 灾难定性打回！
