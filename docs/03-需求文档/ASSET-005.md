# 需求文档：ASSET-005 公共功能与规范

## 1. 实体公共功能需求 (后端与前端要求)
### 1.1 原生功能继承
- **涵盖范围**：新增的五类实体（`AssetCategory`、`AssetCatalog`、`AssetType`、`AssetAttribute`、`DataAsset`）均受此约束。
- **互动组件要求**：上述五类实体，均需支持通过 OpenMetadata 原有框架实现以下四大原生组件的无缝接入：
  1. **点赞 (Up Vote)**
  2. **点踩 (Down Vote)**
  3. **版本历史 (Version History)**
  4. **活动信息流 (Activity Feed)**

### 1.2 物理删除强制规范
- **涵盖范围**：新增的五类实体（`AssetCategory`、`AssetCatalog`、`AssetType`、`AssetAttribute`、`DataAsset`）均受此约束。
- **删除逻辑要求**：上述新增的五类实体**均无需支持逻辑删除功能**。系统设计与 API 实现均必须采用直接物理删除。

## 2. 功能开发规范
### 2.1 代码目录结构规范
- **存储约定**：所有新增的文件（包含前后端）需遵循项目架构规范，**统一在对应目录下创建 `asset` 目录**，并将所有相关文件存放于该目录下，禁止零散存放到其他业务包中。

### 2.2 国际化 (I18N) 要求
- **语言支持范围**：新增功能**必须且仅需支持中文和英文**。系统层面对其他语言暂不做硬性翻译或支持要求。

### 2.3 Elasticsearch 搜索引擎接入
- **索引创建与注册**：新增的五个核心实体都需要并在后端服务注册期间建立并创建其专属的 Elasticsearch 索引。
- **全局搜索能力**：所有新增实体均必须**支持并且接入系统的 ES 搜索功能**，确保能在全局或特定模块搜索入口通过关键词被正常检索（参考 ASSET-004 中提及的高级与默认搜索规范）。
