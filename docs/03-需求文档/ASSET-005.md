# 需求文档：ASSET-005 公共特性集成与全局基建规范

## 1. 需求说明 (Background)
为了确保新增模块可以被有机融入系统的基因组态，所有5个业务域及模块必须执行统一的抽象公共行为策略。

## 2. 验收标准 (AC, Acceptance Criteria)

### 2.1 底层代码工程结构约束
- **AC1**：不论是后端 Java API 或是前端 React 页面，其对应的路由与基础支持文件夹必须整齐划一地建立和限定在具有 `asset/` 前缀命名空间或命名的独立目录包结构内。不可将其随处散布至 Glossary 或 Classification 常规目录下面。

### 2.2 实体级 ES 驱动倒排检索与注册
- **AC2**：新增的全部 5 大新实体集（`AssetCategory`, `AssetCatalog`, `AssetType`, `AssetAttribute`, `DataAsset`），全部需要在后端引擎启动预备阶段注册，并在 ElasticSearch Cluster 内建制独立维护的 mapping 和 index 群。
- **AC3**：通过前端全局搜索栏搜索对应的关键词，必须能够路由到所有被包含实体的名称结果页面列表上。支持部分全文查询或正则搜集。

### 2.3 多语言国际化强行规 (I18n)
- **AC4**：所有前端的硬编码提示、字段 Label、页面菜单名、按钮文字，必须抽离为翻译字典文件内建映射。
- **AC5**：首期发版必须 100% 完整覆盖提供（en-US）与（zh-CN）两套字典集，其它的语言不需适配，如果未有匹配，走 fallback default English 字条，不能在界面流出键位符。

### 2.4 核心反馈与协作互动组件装载
- **AC6 [原生融合]**：这五个全部的新增页面结构模块在实现后端的 AbstractEntity / 前端的详情基盘组件类注入时：必须具备被激活可用的 Up/Down 投喂赞系统。必须引入并适配原有的 Version History Timeline (实体版本迭代全记录) 和最新协作动态交互板（Activity Thread，记录此上承载的发起任务、讨论、以及系统字段更新通知）。

### 2.5 永久抛弃隔离机制重申
- **AC7 [物理驱逐]**：系统严禁对这五个实体体系开放基于 'deleted = true' 状态位的表级逻辑标记隐藏行为。(即从 OM 系统全局软删除能力集上做减法拦截处理屏蔽选项卡及方法入口)，所有涉及删除指令被调用到 DAO 层时都是永久硬删除，被执行后该 ID 下的所有数据实体彻底从持久层抹消，无法在后台被召回重建提取。
