## 2. 需求说明

### 2.1 现状
五大实体模型虽然构筑完毕并有了自用列表，但对外部初访者来说，缺乏全局的大盘视角，无法通过类似仪表盘的页面快速探查或复合搜索某项存在重重目录嵌套背后的深度资产。

### 2.2 目标
在主工作区打造高集成的 “Explore (探索)” 式全景深钻取复合体页面，提供双侧驱动互动和更硬核的高级表达式 ES 引擎接口调度。

### 2.3 范围
- **包含**：前端“概览”页的左侧树折叠渲染、树过滤透传联动交互；右面主视图带 and/or 生成器的高级探索；列表至概览悬浮看版的左右分裂响应动作。

## 3. 需求内容

### 3.1 功能需求

#### 3.1.1 功能列表

| 功能点编号 | 功能名称 | 优先级(MoSCoW) | 简要说明 |
| :--- | :--- | :--- | :--- |
| F-001 | 版式定调大入口 | Must Have | 左树拉开空间，右大视图切分检索和展表。 |
| F-002 | 目录树形下推级联搜索 | Must Have | 左侧所点选的目录名义涵盖必须递归向下包含。 |
| F-003 | 高阶查询生成构筑板 | Must Have | 提供且只能提供逻辑嵌套式的 ES 复合约束句构建。 |

#### 3.1.2 功能详情 (基于 User Story)

**[F-001] 主域导航概览 (参考 3.2.1)**
- **业务目标**：统合前序模型。
- **交互界面描述**：**100% 参照现行的“探索(Explore)”功能页复刻**，作为左侧首个子菜单着陆点。

**[F-002] 树形穿梭拦截器交互**
- **业务目标**：通过分类架构进行大面积框定筛除。
- **业务规则**：左侧装载分类-目录级联的树控件。当用户产生激活焦点的 Check 或 单击 时，事件机制需要联动向底下的表格数据源发出刷新指令。
- **关联判定下推约束**：右下角表格渲染请求的过滤条件中，**必须覆盖被选中目录的本层，及向下无限延伸延展的所有直系叶子节点目录下的全部绑定 `DataAsset` 集合**，而非仅仅只展出该树节点当层的单薄实体项。

**[F-003] 高级布尔运算查询仪**
- **业务目标**：承接复杂特征交叠分析搜索需求。
- **交互界面描述**：搜索工具条默认自带按“资产类型”过滤的预设档。启用高级按钮后，必须利用与原生匹配的语句组件，通过且仅通过带`AND` `OR` 等子组构筑及表达式推演能力的条件编辑器，合成规则集后发往具备 ES 响应能力的底层进行召回。
- **左右概览联动**：列表区呈出后（必须只展示 DataAsset）。当单击记录列表，不仅触发可能的全屏详情页眺望可能，同时必须在列表右部隔间拉起其 “预览(Preview)” 型概要展板。

### 3.2 非功能需求

- **性能需求**：要求依靠 ElasticSearch 构建的缓存聚合机制来应对极快的多重 AND/OR 并发式数据检索及分页请求推算。

## 4. 验收标准

### 4.1 验收标准 (Acceptance Criteria)
> 🚨【重要红线】这里是 QA 进行“测试左移”出题和“开发者自测”的唯一来源！每一条必须是非主观的、可被机器或人明确验证的条件。

- [ ] AC-01: **(布局精准投射检验)** 打开数据资产菜单概览后，视觉和布局排版区块必须与当前的“Explore”版面元素吻集无出入。
- [ ] AC-02: **(无限子集树状包裹穿透率检验)** 资产在树形分类中结构为 A->A1->A1a。如果资产X挂靠于A1a。在左侧选点击 A 时，结果列表必须涵盖资产X。
- [ ] AC-03: **(ES DSL 高阶表达式组合拼装)** 操作者必须能于系统上组合拼盘出例如“ (类型=T1 AND 填写人员=P1) OR (名称含有=Str) ”的树形逻辑式过滤器并提交取得预期过滤的实体数组。
- [ ] AC-04: **(分权与专注渲染)** 列表视图不带且不得展示如“资产属性字典体”此类辅助数据，其展示区纯粹限定为终态 `DataAsset`。

### 4.2 验收测试方案

| 测试场景 | 前置条件 | 操作步骤 | 预期结果 |
| :--- | :--- | :--- | :--- |
| 高级布尔运算树 | 系统内有符合与不符合复杂条件的多条数据垫底 | 1. 打开概览高级检索；2. 组装 `AND/OR` 条件进行复杂下切执行查询操作 | 数据返回严密契合所下放的所有层叠约束，完全吻合条件的数据呈现而杂乱数据被切除。 |
