# 需求文档：ASSET-001 资产分类与资产目录建设

## 1. 需求说明 (Background)
为了对企业海量数据资产进行有序化的规整，我们需要引入一套具备根节点（分类 Category）和其下属多级分支（目录 Catalog）的层级树结构。

## 2. 模块：后端支持
### 2.1 功能描述
构建 `AssetCategory` 和 `AssetCatalog` 的存储模型及其业务实现逻辑。

### 2.2 验收标准 (AC, Acceptance Criteria)
- **AC1 [实体与字段]**：必须成功新增 `AssetCategory`（至少包含 name, displayName, description）和 `AssetCatalog`（必须包含不可修改的级次 `level` 从1开始，可修改排位 `order`）。
- **AC2 [层级关联约束]**：资产分类为树的根，下属可以挂载多个资产目录；资产目录自身支持嵌套，形成多级。
- **AC3 [删除防呆校验]**：执行资产分类或资产目录级的物理删除（需输入`DELETE`确认）前，必须拦截并检查该目录或其下属所有层级子目录中，是否关联有 `DataAsset` 实体记录，**如果有则强制抛出验证异常并禁止删除**。
- **AC4 [批处理能力]**：系统必须支持通过 CSV 全量导出该分类下的所有目录结构，并通过上传 CSV 文件，实现基于名称或ID重述结构的目录批量导入式更新和插入。
- **AC5 [删除类型约束]**：不引入逻辑注销状态（deleted 字段），实行真正的物理落库删除销毁。且此删除同样适用于分类与目录对应的各种原数据（如活动流）。

## 3. 模块：前端页面展示
### 3.1 资产目录概览/分类列表页
#### 3.1.1 功能描述
在左侧侧边栏增加“数据资产 -> 资产目录”菜单，点击后，左侧展现分类列表，右侧展现该分类相关的操作详情。**布局完全参照“术语库”页面。**
#### 3.1.2 验收标准 (AC)
- **AC1**：点击菜单后，页面左侧必须具有 `AssetCategory` 分类列表大纲，且具有“添加资产分类”按钮。
- **AC2**：选中任意分类，右侧必须展示：
  - 按钮组：添加资产目录 (Add Catalog)、Up/Down Vote、版本历史 (Version History)、`...` 更多操作管理。
  - `...` 菜单中必须包含且功能可用的有：导出 (Export to CSV)、导入 (Import from CSV)、重命名 (Rename - name & displayName)、删除 (Delete)。删除时需弹出二次校验弹窗确认输入 `DELETE`。
- **AC3**：右侧主体必须包含两个并排 Tab：**资产目录** 和 **活动信息流**。
- **AC4**：在“资产目录”Tab 内，必须实现类似术语库详情的：可直接编辑的描述、请求更新描述（Request update）、开启对话 (Start thread)、全量展开/折叠功能。并显示其直接下级目录的表格框或列表，每一项支持添加子项、编辑和通过拖拽/表单移动所属层级。
- **AC5**：点击下级的某个条目名称，必须将其正确锚定并跳转至 3.2 章节定义的。

### 3.2 资产目录详情页
#### 3.2.1 功能描述
深入某一个具体的 `AssetCatalog` 时的明细大体看板。**布局参照“术语(Term)”详情页。**
#### 3.2.2 验收标准 (AC)
- **AC1**：页头必须左侧显示 displayName & name，右侧支持 Up/Down Vote / Version / Add / `...` (仅包含 Rename、更改父级目录 Change Parent、Delete)。
- **AC2**：页头的“添加”按钮必须变为复选操作集，支持：在当前节点下创建子节点 `资产目录`，在当前节点名下绑定 `数据资产` 实例。
- **AC3**：右侧核心工作区拆散分为4个Tab栏目：**概览 (Overview)** / **资产目录 (Child Catalogs)** / **数据资产 (Data Assets)** / **活动信息流 (Activity Feed)**。
- **AC4**：数据资产Tab 中以表格形式罗列下设所有（含自己及所有子级叶子结点深度）相关的数据实体对象集。
- **AC5**：概览中展示所有的基本属性与当前层级/排序序号汇总值。
