## 2. 需求说明

### 2.1 现状
当前 OpenMetadata 无“资产分类 (AssetCategory)” 和“资产目录 (AssetCatalog)” 实体。企业面对海量数据资产无法实现多级文件夹的树形归置，管理存在困难。

### 2.2 目标
在 OM 系统内引入资产分类与目录体系，支持前后端一致的多层级树形维护及数据资产的关联挂载。

### 2.3 范围
- **包含**：`AssetCategory` 及 `AssetCatalog` 实体的模型建设、关联级联约束绑定（如防误删）；前端类“术语库”双侧结构的全域联动与增删改；批量导入/导出功能。
- **不包含**：不涉及具体数据资产元数据的填报（此交由 ASSET-003 处理）。

## 3. 需求内容

### 3.1 功能需求

#### 3.1.1 功能列表

| 功能点编号 | 功能名称 | 优先级(MoSCoW) | 简要说明 |
| :--- | :--- | :--- | :--- |
| F-001 | 新增分类与目录实体 | Must Have | 新增 AssetCategory 及多级支持的 AssetCatalog，支持级联保护。 |
| F-002 | 前端分类管理主页 | Must Have | 原生对接术语库左分布大纲格式，支持添加分类与树展开。 |
| F-003 | 资产目录详情面板 | Must Have | 提供“概览”、“资产目录”、“活动信息流”等多Tab及目录的内部子集管理。 |
| F-004 | 批处理管道集成 | Should Have | 支持通过 CSV 对分类目录层级的全量导出与导入。 |

#### 3.1.2 功能详情 (基于 User Story)

**[F-001 & F-004] 实体建模与批处理**
- **业务目标**：确立数据层根基与批操作性能口。
- **业务规则**：`AssetCatalog` 具备**不可修改的层级字段 `level` (首层为1)** 和可修改的排序字段 `order`。
- **级联删除约束（防呆）**：删除资产分类或目录前，必须且**仅能**校验其下是否存在挂载的 `DataAsset` 记录，如果存在禁止删除并报错。
- **输入/输出条件**：
  - 输入：CSV 表单上传，基于名称匹配。
  - 输出：结构的全量覆盖并生成对应的层级目录树。

**[F-002] 资产管理列表页 (参考 3.2.2 资产目录)**
- **业务目标**：导航大盘入口设置。
- **交互界面描述**：**布局必须 100% 参照原有“术语库”页面**。左边为分类列表+“添加资产分类”按键。右侧为分类详情页。右侧上沿必须包含：添加资产目录、Up/Down Vote、版本历史与 `...`下拉管理按钮。
- **`...` 菜单规范**：必须包含导出、导入、重命名、及**带 DELETE 强确认输入拦截的物理删除按钮**。
- **右侧 Tab 区限制**：必须具备“资产目录”和“活动流”。“资产目录”下必须重写术语库一样的 8 核心动作（编辑描述、更新请求、全展开折叠、迁移、批量编辑等）。

**[F-003] 资产目录详情查看 (参考 3.2.6)**
- **交互界面描述**：点击进入特定目录，**布局参照“术语”详情页**。顶部带标识与管理操作（同上有重命名、更改父级、 DELETE 物理删除）。
- **顶层特殊下拉按键**：添加按钮必须拆分下拉提供 `资产目录 (添加下级)` 与 `数据资产 (关联实例)` 两个快捷启动入口。
- **底部 Tab 分屏区限制**：强制分解为**“概览”、“资产目录”、“数据资产”、“活动信息流”** 4大板块。其中“数据资产”列表必须展示该目录及其下一切子代目录的所有关联实例汇聚表。

### 3.2 非功能需求

- **性能需求**：树形目录展开需要能承载1万级以上的节点不产生浏览器渲染崩溃，默认使用懒加载。
- **安全性与合规性**：不设逻辑删除，彻底实行物理层库表注销（基于 ASSET-005 的底层约束）。
- **可用性**：目录关联数据结构变动需要在事务内流转，保证无脏乱外键遗留。

## 4. 验收标准

### 4.1 验收标准 (Acceptance Criteria)
> 🚨【重要红线】这里是 QA 进行“测试左移”出题和“开发者自测”的唯一来源！每一条必须是非主观的、可被机器或人明确验证的条件。

- [ ] AC-01: **(字段结构校验)** 能够成功查阅 `AssetCategory` 实体数据与自带明确层级 `level` 的 `AssetCatalog`。
- [ ] AC-02: **(删除防呆验证)** 用户对某绑定了存活数据资产子节点的目录进行删除时，系统弹出阻断拦截提示并不予落库删除执行。
- [ ] AC-03: **(批处理校验)** 下载样例CSV导出后，修改其中结构层级并导入，界面的目录树能正确联动刷新。
- [ ] AC-04: **(视图合规度检验)** 页面布局精确复刻了“术语库”大框；左侧菜单具有独立路由入口；各层级的“添加”下拉框、包含有要求键入“DELETE”字样的确认提示模态框均完好显示且触发拦截正确。
- [ ] AC-05: **(详情关联数据聚合验证)** 进入某一具有下沿叶节点的目录详情页的“数据资产”Tab下，必须能一揽子展示自身与所有叶节点挂靠的DataAsset汇总值。

### 4.2 验收测试方案

| 测试场景 | 前置条件 | 操作步骤 | 预期结果 |
| :--- | :--- | :--- | :--- |
| 创建与嵌套 | 初始环境 | 1. 创建分类 A；2. 创建目录 A-1；3. 在目录 A-1 创建子目录 A-1-1 | 左侧树形结构呈现 A -> A-1 -> A-1-1 层级。 |
| 删除阻断 | 存在绑定关联记录的数据 | 1. 挂靠一个业务资产至 A-1-1；2. 试着通过 `...` 删除 A-1 | 弹出二次确认弹窗输入DELETE后，系统API报依赖错误拒绝执行，且数据完好。 |
| 解绑销毁 | 将关联数据脱钩后 | 1. 清空 A-1-1 的业务资产；2. 重新触发 A-1 级联删除 | 输入 DELETE 确认后。成功将其抹除，数据库彻底物理清空，无逻辑记录残存。 |
