## 2. 需求说明

### 2.1 现状
平台缺少对“元数据字段组合模板”的管理。无法对数据资产定制化扩展结构（如 API字典、物理表字典具有不同的观测字段）。

### 2.2 目标
构建底层基石级的 `AssetAttribute`池（属性字典）以及基于其组合拼装成的 `AssetType`配置模板，并在呈现时自动基于属性维度归类聚合分组。

### 2.3 范围
- 涵盖类型与属性两层模型建表，支持字段鉴权绑定，前后端字典管理，前端模板类“分类页”结构还原以及特定的 Tab 动态拉起逻辑。

## 3. 需求内容

### 3.1 功能需求

#### 3.1.1 功能列表

| 功能点编号 | 功能名称 | 优先级(MoSCoW) | 简要说明 |
| :--- | :--- | :--- | :--- |
| F-001 | 资产属性底座字典建设 | Must Have | 管理所有可用的底层字段元器件。 |
| F-002 | 资产类型组合装配版 | Must Have | 提供模板化挂载属性形成数据填报蓝图。 |
| F-003 | 前台动态响应分组解析 | Must Have | 基于包含的属性大类归口，前端生成动态视图 Tabs。 |

#### 3.1.2 功能详情 (基于 User Story)

**[F-001] 资产属性底座维护 (参考 3.2.4与3.2.7)**
- **业务目标**：生成一个全局可复用的元字段仓库。
- **业务规则**：每个属性必须定义：`属性分类` (枚举如：基本/业务等)，`数据类型` (String/Int等)，以及关键的 `填写人员` Role 清单（用于后期表单修饰权限），`是否必填` (暂不作后端强制约束)。枚举需要打底默认值并提供后续的系统可延展扩展能力。
- **交互界面（总列表）**：**参照原有“自定义属性”页面**。提供搜索+属性分类筛选二合头。操作栏带入批量导入与导出按钮。下方表格的对应名称点击后进入详情页面。
- **交互界面（单详情）**：**参照原有“标签”详情页布局**。页头有 `...` 的下拉，内提供重命名、且需要键入 **DELETE** 确认的物理删除保护。下切“概览”和“活动流”双页卡展现全貌。

**[F-002 & F-003] 资产类型拼装与动态分组解析 (参考 3.2.3)**
- **业务目标**：生成特定场景数据资产的载体框架。
- **交互界面描述**：**参照原“分类(Classification)”页面**分布。左列清单，右设明细详情。右侧包含添加挂载属性和基础按钮，**删除同样必须通过 DELETE 回归校验拦截**。
- **动态解析渲染机制**：这是核心表现逻辑。用户查看资产类型详情下半屏时，前端代码**必须抽取当前类型所引挂的全部 `AssetAttribute`，读取各自带有的 `属性分类` 参数去重聚合，由此自动铺展并生成 N 个与之对应的独立名称 Tab卡**（例如系统识别到此模版绑了 基本类 和 业务类 属性，必须吐出 “基本信息”、“业务信息”、“活动信息流”三个 Tab 夹供切替）。
- **Tab 内部交互**：点击这些动态生成项后，以**列表表格**的形式铺开属于这一大类的资产属性们，并提供逐个配置解绑管理动作。

### 3.2 非功能需求

- **可扩展性**：支持不同的 AssetType 实体交叉复用同一个 AssetAttribute。字典结构要灵活且低耦合。

## 4. 验收标准

### 4.1 验收标准 (Acceptance Criteria)
> 🚨【重要红线】这里是 QA 进行“测试左移”出题和“开发者自测”的唯一来源！每一条必须是非主观的、可被机器或人明确验证的条件。

- [ ] AC-01: **(属性与类别字段齐备性)** 新增 `AssetAttribute` 具备 `属性分类`、`数据类型`、`填写人员角色集`、`是否必填` 四要素。
- [ ] AC-02: **(实体交叉复用)** 创建一个“描述”的共同属性，能在类型 A 和类型 B 的操作面板中，分别将其复用添加入其管理池子且互不干扰影响业务逻辑。
- [ ] AC-03: **(界面重现匹配度)** 前端对应页面的基础布局和 Tab 切割比例 100% 对应指定的页面（“自定义属性”、“标签”、“分类”）。
- [ ] AC-04: **(动态视图生成准确率)** 当在类型中添加3个不同归口（基础、技术、安全）的属性后，前台对应的详情明细界面下方，原本的 Tab 组会自动撑开并准确显示对应的文字分类选项板，切入后分别只陈列符合其归口范畴的数据集。

### 4.2 验收测试方案

| 测试场景 | 前置条件 | 操作步骤 | 预期结果 |
| :--- | :--- | :--- | :--- |
| 动态分组渲染机制测试 | 备好三项不同的资产属性且隶属两个不同的基础分类 | 1. 建立空类型 A；2. 向内置入以上三项属性；3. 查看并切回 A 详情面板页面 | 下层 Tab 标题组依据绑定的三大属性所对应的大分类准确生成 2 个分类 Tab。 |
