# 需求文档：ASSET-002 资产类型与资产属性

## 1. 需求说明 (Background)
资产类型是一组资产属性的模版集合。定义好一系列基本、技术或业务属性后，将它们组合成为一个具体的“类型”（例如：API接口类型、指标类型）。在此基础上衍生出的实际数据资产将继承其动态表单展现能力。

## 2. 模块：后端支持
### 2.1 功能描述
构建统一管理的定义库：`AssetType` 和最原子的特征集配置字典字典 `AssetAttribute`，维持多对多关联或引用关系。

### 2.2 验收标准 (AC)
- **AC1 [属性管理]**：实现 `AssetAttribute` 的 CRUD。字段必须包含：`属性分类` (Enum: 基本/技术/业务/质量/安全)，`数据类型` (Enum: 字符串/数值/日期/布尔/文本/数组)，`填写人员` (List<Role>，指定拥有的角色)，`是否必填` (Boolean)。**当前阶段后端不需要真正执行必填字段的卡点拦截校验**。
- **AC2 [枚举扩展]**：属性分类枚举与数据类型枚举支持通过“自定义属性系统”扩展，必须内置默认的上述固定初始值列表打底。
- **AC3 [类型与属性聚合]**：实现 `AssetType` 的 CRUD。类型必须维护一个持有的关联 `AssetAttribute` 表列。允许不同的 AssetType 引用同一个 AssetAttribute 即共用同一个引用基准。
- **AC4 [批处理流]**：支持批量维护 `AssetAttribute` 和 `AssetType` 所持有属性绑定的 CSV 上传/导出通道。

## 3. 模块：前端页面展示
### 3.1 资产属性管理页
#### 3.1.1 功能描述
全局资产属性登记本。**布局参照“自定义属性 (Custom Properties)”页面。**
#### 3.1.2 验收标准 (AC)
- **AC1**：位于左侧 “数据资产 -> 资产属性” 菜单并展示总表。
- **AC2**：表头按左侧结构设置支持 **搜索框**（模糊匹配 Name/displayName/description），以及基于 **属性分类** 的下拉聚合过滤选择器。
- **AC3**：右侧表头按钮区提供“添加资产属性”、“导入(Import)”、“导出(Export)”。
- **AC4**：下方表格记录必须能体现各个细粒度字段表现形式，名称自带 `href`，可由链接跳转或侧边栏弹出该属性细则，支持同行操作区的快速修改和删除防呆拦截（如果有类型在占用）。

### 3.2 资产属性详情页
#### 3.2.1 验收标准 (AC)
- **AC1**：页头左显名称与展示名，右提供 Up/Down/版本以及包含 `Rename`与物理 `Delete` 的操作符集。
- **AC2**：下辖双表单标签块（Tab组）：**概览 (Overview)** / **活动信息流 (Activity Feed)**，必须能罗列包含：数据类型，所属大分，权限白名单（填写人员），是否必填等。在活动中自动注入OM通知中介逻辑。操作时支持在线直接保存更新属性核心数据（除主键限制外）。

### 3.3 资产类型主页
#### 3.3.1 功能描述
维护具体的模板壳。**布局参照“分类 (Classification)”页面。**
#### 3.3.2 验收标准 (AC)
- **AC1**：点击 “数据资产 -> 资产类型” 菜单，采用“左导航+右详情”并肩模式布局。
- **AC2**：左侧必须常驻列举当前系统的所有 `AssetType`，底部（或顶部）设有“添加资产类型”快速创建入口。
- **AC3**：选中后，右侧面板顶层展示类型基础面及按钮行：Add Asset Attribute (将系统预设库内的相关项挂在自己名下)、Up/Down、History、Delete & Rename。
- **AC4**：右侧面板下层**必须基于该 AssetType 名下挂载的所有 AssetAttribute，提取其 `属性分类` 字段去重后，动态生成一排响应式 Tab 切换夹**。
- **AC5**：如包含“基本/业务”，必须渲染由这 2+1（活动信息流）组成的至少 3 个 Tab 页。
- **AC6**：点击任一动态分类 Tab，其下呈现的列表中仅筛选出归属该大类的相关 `AssetAttribute` 清单，提供局部的配置修改或与该资产类型的解绑删除按钮（非从系统删除）。并支持点击名称跳转。
